Review was designed for changes a person wrote.

A coding agent can open twenty pull requests before lunch. Each one is larger than it needs to be, because writing more code costs the agent nothing. Reading it costs you an afternoon.

A diff asks for the same attention on every line. Nobody has that much attention, so review becomes a skim and an approval. The name on the merge is still yours.

A second model leaving comments on the diff does not change this. It gives you more text to read and no evidence you can check.

The useful question is narrower: which of these lines does the request need, and what did the agent add that nothing tests?

Remove a block. Run the tests. Keep what breaks them.

If a test fails without a block, the request needs it. If every test still passes, nothing checks that block: it is extra, or it is untested. Tieto reports which blocks, and does not guess which of the two.

What a trim does not prove.

  • Needed is not the same as complete. It means a test fails without the block. If the tests miss a requirement, so does the trim.
  • Unchecked means extra or untested. Tieto cannot tell which, so those lines go back to the author. They are never dropped silently and never merged.
  • A named person still decides. Nothing merges until you click, and it merges as your GitHub account.
  • Some risk is outside the tests. Hardware behaviour, performance and anything else the test suite does not exercise still needs a person.
